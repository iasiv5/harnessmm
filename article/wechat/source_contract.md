## 论文事实（均为论文主张，引用时注明"论文报告"）

1. [PAPER] 论文标题：HarnessMM: Recursive Self-Improvement for Harness Token Efficiency；作者来自清华大学与微软亚洲研究院；HarnessMM = Harness Minus Minus（摘要原文）。
2. [PAPER] 核心机制（§4.1-4.3）：慢推理一次产出当前动作 + 可执行决策图（EDG），节点含完整字面参数、前置依赖、公共守卫；图跨工具反馈保留（GDR），守卫只对照真实回执求值；条件满足时直接执行已存动作、跳过原定模型回调（CCS），并留替代证书供审计。
3. [PAPER] 回退条件：守卫失败、条件不明、出现新语义判断、选择器弃权时，控制权交回慢推理（§4.2）。
4. [PAPER] 论文报告数字（非本项目结果）：HumanEval 上 Codex 成功率 90.82% 保持不变，Tokens/task 66.72k→47.02k（省 29.54%）；DeepSeek Harness 71.43%→85.71%，96.28k→11.62k（省 87.93%）；MBPP 消融：持续复用比"单次图"省 26.91% 成本、比"保留回调"省 19.52%。
5. [PAPER] 论文自己声明的局限（§6）：节省依赖供应商输入/缓存/上下文记账方式与已解决动作的可得性；新语义决策仍需慢推理；创作、选择与恢复的开销可能超过被省掉的调用。

## 实验事实（本项目一手数据）

6. [F1] 任务：约 80 行 Python 配置解析器；初始版本只支持十进制端口，"0x1F90" 被拒。初始状态：单元测试 7 failed / 20 passed；集成测试 2 failed / 3 passed；产物校验 FAIL。
7. [F1] 模型 glm-5.3-flash，temperature 0.1，thinking 关闭；全部调用为真实 API 调用，usage 为供应商实测值。
8. [F1] 共同修复阶段：16 次调用（38,300 in / 2,714 out tokens）；期间 1 次工具拒绝（模型记错测试文件名）后自行纠正；独立评分器 PASS 后保存共同检查点。
9. [F1] R1（每步回调基线）：5 次调用执行 4 条验证命令（4 次动作决策 + 1 次完成总结），本臂 27,430 tokens。
10. [F1] R2（持续决策图）：第 1 次调用同时提交当前动作与 3 节点决策图；正式运行中 2 个节点经 bypass 证书直接执行（每次绑定替代证书，边界上无模型请求）；共 3 次调用、19,331 tokens。中途模型把守卫写成 `stdout_contains: "PASS"`，而守卫对照的是前置构建回执（输出为 `BUILD OK`，不含 PASS）→ 运行时判定守卫失败、剩余图失效、回退模型；模型重跑校验命令确认 `ARTIFACT VERIFY: PASS` 后完成。
11. [F1] R3（故障注入）：工具层注入一次真实失败（pytest 真实退出码 1）；下游构建/校验节点被阻断，图失效，真实回退调用模型；模型在新图上重试，集成测试通过后构建与校验节点自动执行成功。共 3 次调用、20,094 tokens、3 次 bypass。
12. [DEV] 开发运行（同配置）：R2 仅 2 次调用（无守卫失误时的顺利形态）；说明回退路径本身有成本。
13. [F1] 每条记录通过 10 项结构审计（图先于执行保存、参数哈希一致、前置回执满足守卫、节点不重复执行、bypass 无模型请求、故障后下游阻断、回退有真实请求、工作区变更使图失效、回放与事件哈希一致等）；回放页为只读静态 HTML，由事件重新生成。
14. [F1] R2 vs R1 本臂 tokens：27,430 → 19,331（↓29.6%）。该数值与论文 HumanEval 的 29.54% 为数字巧合，总体、任务、协议、口径均不同，不构成相互印证。
15. [F1] 缓存命中差异大：R1 16,640 cached tokens，R2 7,360——成本对比对供应商记账方式敏感。
16. [F1] 共同前缀口径：三臂共享修复阶段成本（16 次调用），分臂展示时"含前缀"行只列示不重复计入结论。
17. [INFRA] 假模型夹具（22 项测试）验证执行器语义：守卫求值、参数完整性、节点单次执行、故障阻断、工作区变更失效等。
18. [F1] 未实现：RSI、提示词自动优化、上下文压缩、模型选择器（用确定性规则代替）。单任务结果不做泛化声明。
