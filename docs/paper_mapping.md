# HarnessMM 机制映射与设计说明

本文档回答四个问题：原文机制是什么、本项目怎么实现、哪里做了简化、这些实现**不能**用来证明什么。
论文原文：https://arxiv.org/html/2610.32813v1（arXiv:2610.32813v1, cs.AI, 2026-10-23）。
以下论文事实均标注章节位置，数字仅作为"论文主张"引用，本项目不依赖这些数字成立。

## 1. 论文机制核实结果（基于原文）

| 概念 | 原文定义与约束 | 出处 |
|---|---|---|
| **EDG**（Executable Decision Graphs，可执行决策图） | 慢推理在第 i 次决策时，除当前动作外还产出一张有界可执行延续图 G_i=(V_i,E_i)。未来决策节点 B_i={d_1..d_m}，每个 d_j=(a_j, arg_j, pred_j, g_j)：原生动作、**完整字面参数**、前置节点、公共执行守卫 g_j: S_public→{true,false}。守卫在创作时固定，由适配器对照**后续实际观察到的回执**求值。边连接根或更早节点，构成无环图。回执缺失或拒绝则阻止入场；空图交还慢路径。 | §4.1，式(4) |
| **GDR**（Guarded Decision Reuse，守卫式决策复用） | 图**跨工具转移保留**。资格判定 eligible(d_j,s_t) = 1{前置完成} · 1{g_j(s_t)=true} · 1{arg_j 封闭}。守卫只消费已观察回执、从不消费预测结果；不支持的观察、未满足的依赖、需要新推理的参数，都交还 H_0。每次执行的回执继续更新同一张图。 | §4.2，式(5) |
| **选择器** | Jev 风格的**类型化选择器**：返回合格候选 ID 或弃权（abstain），不能修改参数。唯一合格节点可确定性执行；空集与弃权调用慢路径。实现中单 token 解码 + logprob。 | §4.2, §2 |
| **CCS**（Certified Callback Substitution，认证回调替代） | 把已入场的 GDR 决策变成下一个慢回调的可执行替代：s_t→d_j→a_t（而不是 s_t→H_0→a_t），经**原始工具接口**执行。替代证书 κ_t=(graph_hash, decision_id, predecessor_receipt, exact_args, tool_receipt, bypassed_callback_id)。审计要求 N_slow_parent − N_slow_HarnessMM ≥ 1，即被跳过的边界**没有对应模型请求**；不预测未观察的响应或 token 数。 | §4.3，式(6)(7) |
| **完整任务记账** | C_episode = Σ(T_in+T_out)，** charged：图创作、选择器输入输出、新增上下文、剩余慢调用、回退、恢复、收尾、失败的付费执行。缓存输入照算。开发成本 C_dev 单独报告。共享创作只记一次到声明的 cohort。 | §4.4，式(8)(9) |
| **参数封闭（closed args）** | 由 schema 和候选成员检查强制；"先前的推理是否正确解决了该动作"是**语义假设**，由任务评分评估。"守卫通过"只证明其声明的公共条件成立，**不证明任务语义正确**。 | §4.2 |
| **RSI**（递归自我改进） | 在**任务外**迭代精炼伴随 harness 配置：当前 harness 给训练反馈，验证集选出候选并**在测试前冻结**。参与者权重、路由、执行代码、任务接口、评分器、输出上限全部固定。RSI **不是**模型权重训练，也与任务内决策复用分离归因。 | §1, §2, §5.6, 附录 B.2 |
| **替代悖论** | 只有当被消除的推理 > 新增的创作+选择+恢复成本时才真正省钱（式(3)）。短输出本身不构成回调消除的证据。 | §3.3 |
| **消融边界** | MBPP-sanitized 257 题：Full 13.17k tokens/题；W/o GDR（单次图）18.03k（持久复用省 26.91%）；W/o CCS（保留回调）16.37k（省 19.52%）；W/o EDG 执行 16.19k 且成功率反而更高（95.33% vs 93.77%，少解 4 题换来 18.62% 更贵）。论文明确：集成 harness 的总调用差**不是**证书的孤立效应。 | §5.5, Figure 4, 附录 E.1 |
| **局限（原文自述）** | 节省依赖供应商输入/缓存/上下文记账与已解决动作的可得性；新语义决策仍需慢推理；创作、选择与恢复可能超过被省掉的调用；公共状态适配器是任务特定的；小开发集下策略级质量差异不确定。 | §6 |

## 2. 机制映射：原文 → 本项目实现

| 原文机制 | 本项目实现 | 说明 |
|---|---|---|
| 慢推理产出当前动作 + EDG | 修复完成后，模型在一次真实调用中产出「当前命令 + JSON 决策图」（链式节点，每个节点含完整 argv、前置、守卫） | 图由模型真实生成，程序不补写任何节点或参数 |
| arg_j 完整字面参数、封闭性检查 | 节点 schema 强制 `args` 为完整字面 argv 数组；执行时逐字节对比 `authored_args_hash` vs `executed_args_hash` | schema 校验 + 执行哈希双重检查 |
| g_j 公共守卫，只消费已观察回执 | 受限结构化守卫：`{"exit_code": 0, "stdout_contains": "..."}`（可选字段），由执行器对照真实回执求值；不支持任意代码 | 不执行模型提供的代码；字段缺失→unknown；不匹配→failed |
| GDR 跨反馈保留图、回执更新图 | 执行器在每个工具返回后重查剩余节点资格；图对象持续保留直到耗尽/失效 | 实现于 `harness/executor.py` |
| 类型化选择器：候选 ID 或弃权 | 确定性选择规则：链式图中"前置完成且守卫为真且参数封闭"的节点按序取第一个；0 个或 ≥2 个均视为不明确→回退模型 | 教学简化：不用模型选择器，用公开确定性规则（首版要求链式图，天然唯一合格） |
| CCS 证书与审计 | 每个 bypass 事件绑定 (graph_id, node_id, 前置回执 id/hash, authored/executed args hash, tool_receipt_id/hash, bypassed_boundary_id)，且事件中 `model_request_id=null` | 实现于 `harness/events.py` + `tools/audit.py` 检查 6 |
| 回退：守卫失败/未知/新语义需求→H_0 | 守卫 failed 或 unknown、图格式非法、工作区哈希不匹配时：剩余图失效，真实调用模型并附真实回执 | 模型失败/弃权/解析失败原样记录，不修成成功案例 |
| 工作区变更→旧图失效 | 图创作时记录 workspace_hash；执行器每次执行前重算，不匹配→invalidate（事件记录原因） | 对应原文"图失效"要求与本项目检查点 9 |
| 完整任务记账 | 统一模型入口记录每次调用的 provider usage；图创作、回退、最终总结、失败重试全部入账；bypass 边界不产生任何请求记录 | 实现于 `harness/llm.py` |
| RSI（任务外配置优化） | **不实现**。本项目只复现任务内执行机制（GDR+CCS），首版明确排除 RSI、提示词自动优化、上下文压缩 | 用户设定 + 论文自身将其分离归因 |

## 3. 教学简化与工程近似（全部公开）

1. **选择器简化**：不用模型/单 token 选择器，改用确定性链式选择规则。原因：教学任务图小且链式，唯一合格节点可直接判定；论文 §4.2 也承认"唯一合格节点可确定性执行"。
2. **守卫表达受限**：只支持 exit_code 相等与 stdout/stderr 包含检查，JSON schema 校验字段白名单。论文的 g_j 是一般公共状态谓词，本实现是其小子集。
3. **单任务、单语言、无泛化声明**：论文在 HumanEval/MBPP/ALFWorld 等完整 cohort 上评估；本项目在一个 ~80 行的配置解析器教学任务上展示机制事件。
4. **故障注入是环境真实失败**：R3 在集成测试工具层通过环境变量触发一个真实的 pytest 失败（子进程真实退出非零），一次性触发并全程标注。这不是论文机制的一部分，是为展示回退路径人为构造的教学装置。
5. **每步一动作的 R1 是实验控制**：R1 强制每次模型决策只执行一个独立验证动作，这是受控基线，不代表普通 Agent 的能力上限（普通 Agent 可以合并命令）。
6. **凭证式账本**：bypass 以"事件 + 回执哈希"证明，不假设每个 bypass 等于某个固定 token 值（与论文"no per-certificate token value is assumed"一致）。

## 4. 本项目结果不能证明的结论

- ❌ 不能证明 HarnessMM 在一般任务上优于普通 Agent、脚本或工作流引擎。
- ❌ 不能把单任务调用次数/Token 差异泛化为普遍节省；token 是否下降取决于已解决动作的可得性（原文 §6）。
- ❌ 不能把"审计通过"解释为"任务语义必然正确"（原文 §4.2：守卫通过只证明声明的公共条件）。
- ❌ 不能把任务内决策复用解释为跨任务技能学习；本项目未实现 RSI，不能宣称任何"递归自我改进"。
- ❌ 不能把"未观察到错误"写成"证明无损"；结构与参数一致性审计不替代语义验证。
- ❌ 论文报告的任何数字（29.54%、87.93%、26.91% 等）只是论文主张，与本项目实测无关。

## 5. 钢人评估（实施前记录）

**支持本方案的最强理由**：透明的小任务足以让"决策提前生成、跨反馈保留、回调省略、异常回退"四类机制事件全部可观察、可审计，且证据链（图 JSON + 事件 JSONL + 回执 + 审计报告 + 回放）完整可复核。

**反对本方案的最强理由**：(a) 任务可能天然适合脚本化——四条验证命令可直接写成一个 shell 脚本，决策图的"价值"在人设任务里显得刻意；(b) R1 的"每次只执行一个动作"是人为约束，会放大 R1 的调用次数，制造对 R2 有利的对比；(c) 单任务无法证明泛化收益，也不应暗示。

**处理方式**：
1. 项目定位为**机制复现**（mechanism demonstration），从头到尾不用"性能复现"表述；
2. 所有人为控制写入冻结配置并在文章中公开；
3. R1 明确标注为受控逐步回调基线；
4. 明确承认固定流程可以直接写脚本——文章专设一节回答"为什么不直接写脚本"；
5. 不预设 Token 必须下降；实测结果如实报告，包括成本上升的情形；
6. "未观察到错误"只表述为"审计通过"，不表述为"证明无损"。

## 6. 关键设计取舍记录

| 取舍点 | 决定 | 理由 |
|---|---|---|
| R2/R3 是否共享图创作前缀 | **不共享**：R2、R3 各自从检查点 C0 出发，各自真实调用模型创作决策图 | 避免"同一次调用记两次"的记账歧义；每条臂成本完全可归因。代价是图内容可能因采样不同而不同——这正是真实运行，不做人为对齐 |
| 可选附录组（单次图模式） | **不实现** | 与 R1（无图）对比已能说明"逐步决策 vs 提前创作"；单次图会增加实现面而不增加关键洞察 |
| 自由执行基线 | **不实现** | 首版聚焦三条主记录；预算允许时作为后续补充（README 记为未完成项） |
| 模型选择 | glm-5.3-flash（Z.AI Coding CN / bigmodel.cn 端点），thinking 关闭，temperature 固定 | 本机 DSH 已配置的真实 provider，OpenAI 兼容、返回真实 usage 与 request_id |
| 每臂预算上限 | 见 `harness/config.py`（冻结后不再改动）：每臂模型调用 ≤ 16，公共修复阶段 ≤ 24，单次调用超时 120s，重试 ≤ 2（仅传输类错误） | 防失控；触发上限即记录并停止 |
| 事件序号与因果 | 每条 run 一个单调 sequence；事件携带 prior_receipt_id 与 content hash，不依赖时间戳排序 | 满足审计可复核 |
| 测试防篡改 | 检查点保存 tests/ 的原始内容哈希；独立评分器先校验 tests/ 哈希未被改动，再用**自带的**独立向量直接测工作区解析器 | 防止被测模型改测试"通过" |
